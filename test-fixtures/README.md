# 测试素材（照片）

这些文件**不入库**（共 13MB），用脚本生成：

```bash
python scripts/make_fixtures.py
```

需要 Pillow：`pip install pillow`。

所有图片都是程序生成的颜色块 / 噪声，不含任何第三方素材，没有版权问题。

## 每个文件用来测什么

| 文件 | 预期结果 |
|---|---|
| `01-too-small-240.png` | 240×240，低于 320px 下限 → **拒绝**，提示"太小了" |
| `02-normal-2000x1500.jpg` | 正常横图。放在 108mm 宽的框里约 470 DPI → **无提示** |
| `03-huge-6000x4000.jpg` | 会被降采样到长边 3000px 再存，验证内存不炸、画面不糊 |
| `04-portrait-exif6.jpg` | 带 EXIF 方向 6（需顺时针转 90°）。上传后应当**竖着显示**，取景框对得上 |
| `05-transparent.png` | 圆形区域透明。放在深色模板上应露出底色，不应出现黑块 |
| `06-corrupted.jpg` | 内容是文本、后缀是 jpg → **拒绝**，提示"解不开" |
| `07-over-8mb.jpg` | 12.7MB → **拒绝**，提示体积超限 |
| `08-panorama-4000x300.jpg` | 极端宽高比，用来测取景框夹取是否越界 |

## 手工验证清单

1. 逐个上传，确认拒绝的四张（01 / 06 / 07）给的是**可读的中文提示**，不是英文异常
2. 上传 `04`，确认画面是正的，不是躺倒的
3. 上传 `05` 到深色模板（生日·夜色），确认透明区露出底色而不是黑色
4. 上传 `08`，拖到最左最右，确认不会露出空白边
5. 上传 `03` 后看任务管理器，浏览器内存不应暴涨（正常应 < 300MB）

## 自动化

纯计算部分有单元测试，不依赖这些素材：

```bash
node scripts/test-photo.mjs   # 需先 esbuild 打包，见 README
```
